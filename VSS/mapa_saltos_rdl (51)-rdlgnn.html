2Validate your data

Generates a profiling query from the analyzed schema; run it on your engine and paste the result here to check your data quality before RelBench.
What does the profiling query compute? (for data science)
It is a single read-only query (it changes nothing) built from the schema you pasted: for each table it runs a SELECT with aggregates and joins them with UNION ALL in long format tabla, columna, metrica, valor. The result is a single table you paste here, no matter how many tables you have. For CSV/Parquet it does the same with DuckDB from Python. It scans each table once per metric group, plus one JOIN per FK (orphans) and one LAG window per time relationship (rhythm).
MetricWhat it measuresHow it is computedWhy it matters for RDL
filasSize of each tableCOUNT(*)Each row is a graph node; the sum is the graph size.
pk_nulos, pk_duplicadosPrimary key qualityNull PKs; COUNT(pk) − COUNT(DISTINCT pk)RelBench requires a unique PK: a duplicate means two nodes with the same id.
tiempo_min/max, tiempo_nulos, tiempo_futuroRange and quality of the time columnMIN/MAX after casting to timestamp; count of nulls and of dates > todayDefines from when to when you can cut train/val/test; a null or future date breaks the temporal filter (leakage).
filas_mes_primero/ultimo/medianaMonthly volumeCount per month of the time column: first month, last month and medianDetects incomplete months at the start or end (don't put the test split in a half month).
fk_nulos, fk_huerfanasIntegrity of each relationshipNull FKs; LEFT JOIN to the parent where the parent doesn't existEach FK is an edge: nulls = loose rows; orphans = edges to nodes that don't exist.
nulos_pct, distintos, min, maxProfile of each non-key column% nulls, distinct values (approx. in economy mode), range if numericNearly empty columns or with one distinct value per row (free text, IDs) add nothing as tabular features.
entidades_con_eventos, mediana/p90_dias_entre_eventosRhythm: how often an event happens per entityFor each table with time and its parent: LAG(time) OVER (PARTITION BY fk ORDER BY time), median and p90 of the days between consecutive eventsThe median suggests the prediction window; the p90, how many days without events before an entity stops counting as “active”.
mismo_ts_padre_pctWhether the child is born at the same instant as the parent% of rows with the same timestamp as their parent (JOIN on the FK)Distinguishes detail tables (order_item of orders) from events of their own.

What does each option mean?
      

      
ControlWhat it isValues

      
ModelThe rule each node uses to combine its neighbors in each layer (the formula).Heterogeneous GraphSAGE: mean of neighbors per relation + its own vector; RelBench's default and the best starting point.
R‑GCN: one matrix per relation with a normalized sum; simpler and with fewer parameters.
Attention (GAT / HAN): learns how much each neighbor weighs; useful when a few neighbors matter much more; more expensive.

      
ActivationThe nonlinearity σ applied after combining. Without it, several layers equal a single linear transformation.ReLU max(0, x): the standard.
LeakyReLU: lets a little of the negative through; avoids “dead” neurons.
GELU: smooth curve, common in transformers.
ELU: smooth on negatives. Sigmoid and softmax are used at the output, not in hidden layers.

      
Dimension dHow many numbers each node's vector has (hidden channels).32 / 64 / 128 / 256. Bigger = more capacity, more memory and more overfitting risk with little data. 64–128 is typical (RelBench uses 128).

      
TaskWhat the head produces and how the error is measured. Defined by the task table (block 11).Classification: 1 logit → sigmoid → p; binary cross-entropy loss.
Regression: a number ŷ; absolute error (MAE) or squared error (MSE) loss.

      

      
Fixed in all models: Adam optimizer, backpropagation, LayerNorm between layers and the number of layers/neighbors from blocks 3 and 9.

    

    
Formulas of the chosen model

    

    
The formula and activation depend on the model. RelBench ships heterogeneous GraphSAGE with ReLU and LayerNorm; R-GCN and the attention models (GAT, HAN, HGT) are in PyTorch Geometric and can be swapped in the same pipeline. Parameter counts are approximate.

15Comparison: does RDL beat the simple stuff?

    
Run in this order: baselines_rdl.py (block 13) → rdl_pipeline.py (block 14) → comparar.py. The last one trains an XGBoost on the embeddings exported by the GNN (hybrid, with early stopping on val) and puts everything in one table with val and test.

    

      
If you see…It means

      
RDL > rules A/BThe GNN learns something beyond “what happened last time”.

      
RDL ≈ or > LightGBM / XGBoostIt matches or beats hand-crafted features, without you writing them.

      
RDL+XGB hybrids > RDL and > models C–HEmbeddings and trees complement each other: combining them is worth it.

      
RDL < LightGBM / XGBoostLayers, shortcuts, epochs or data are missing; or the pattern fits in 1 hop and simple features are enough.

    

    
Look mainly at the test column: val was used to pick the best epoch and for early stopping. With synthetic data you only check that everything runs.

    
val was used to make decisions (best epoch, early stopping), so it is somewhat optimistic; test was never used for decisions and is the honest measure.

    
Why another XGBoost?
The block 13 XGBoost uses the 30 features built with SQL. The hybrid uses as columns the embeddings the GNN learned (and, in the second hybrid, “embeddings + features”, the features too). This measures whether what the network learned adds something the manual features don't have.

    
How to run it

    
comparar.py · reads baselines.json, rdl.json and embeddings_*.parquet; saves ./resultados/comparacion.csv
